# R11-11 — UTF-16/Search (Byte/UTF-16 Mapping, Wrap Search, Chinese/Emoji)

- 基线与前置：本 Atomic 建立在本地 R11-10 Index Builder 改动之上。沿用用户在本轮明确指示的方针——不再以真实 CI 结果作为开始各 Atomic 的前置条件，仅依赖本地验证结果推进。
- 任务书依据：执行 Stage 11 Atomic 11.11 UTF-16/Search。目标是把字节/UTF-16 双向映射与 wrap 搜索算法从 `document_store.rs` 提取到独立文件；必须产出位置结果逐例一致。
- UTF-16 边界：新增 `src-tauri/src/document_store/index/utf16.rs`，拥有 `index_utf16_to_byte`/`index_byte_to_utf16` 两个函数——原样迁移自 `document_store.rs` 同名顶层函数，函数名、参数顺序、错误文案（“搜索位置超过文档长度”“搜索位置落在代理字符中间”“搜索结果不是有效 UTF-8 边界”）逐字保留，仅依赖 `index::builder::DocumentIndex` 的检查点数组，不涉及整篇索引构建或搜索算法本身。
- Search 边界：新增 `src-tauri/src/document_store/index/search.rs`，拥有 `search_document_content(content, index, query, from, wrap) -> Result<Option<DocumentSearchMatch>, String>`——原样迁移自 `search_document_state` command 内联的查找逻辑（起点钳制到 `utf16_length`、转字节偏移、正向 `find`、未命中且允许 wrap 时从文档开头再 `find` 一次并置位 `wrapped`、命中后转回 UTF-16 偏移、`to = from + query.encode_utf16().count()`），返回类型改为 `DocumentSearchMatch { from, to, wrapped }` 结构体供调用方按字段读取，语义与原内联代码逐行一致。
- 编排保持：`document_store.rs` 的 `search_document_state` command 收窄为：构建/取用缓存索引 → 调用 `search_document_content` → 无匹配直接 `Ok(None)`，命中则把 `DocumentSearchMatch` 的三个字段映射进 `SearchDocumentResponse`。Tauri command 名称、参数、`SearchDocumentRequest`/`SearchDocumentResponse` DTO 未变。
- 导入清理：`document_store.rs` 顶层不再需要 `index_utf16_to_byte`/`index_byte_to_utf16`（完全内聚进 `index::search`/`index::utf16` 内部，调用方只需要 `search_document_content`），`use index::{...}` 收窄为 `ensure_document_index, search_document_content, DocumentIndex`（`DocumentIndex` 仍因 `StoredDocument.index` 字段类型需要保留）。
- 测试迁移：`document_store.rs` 原有的 `maps_utf16_and_byte_offsets_through_sparse_checkpoints_for_emoji`（R11-10 阶段性保留、验证仍留在原地的两个 UTF-16 函数）随函数一并删除，未在原位置保留重复断言；等价覆盖现由 `index/utf16.rs` 自带测试提供。
- 兼容夹具：`document_store_compatibility.rs` 无需改动——`chinese_and_emoji_search_freezes_utf16_offsets_and_wrap_behavior` 端到端测试保持不动、继续通过，验证的正是本次迁移要求的“位置结果逐例一致”这一交付物；本次迁移未涉及任何新增冻结 token 所在文件。
- 新契约测试：`index/utf16.rs` 自带 5 项单元测试——中文/Emoji 字节↔UTF-16 往返、超出文档长度报错、命中代理字符中间报错、超出内容长度报错、非字符边界报错（后三项是原实现里从未被现有测试单独覆盖过的错误分支，此次迁移顺带补齐）。`index/search.rs` 自带 5 项单元测试——从指定 UTF-16 偏移起正向命中、未命中且允许 wrap 时从头部命中并置位 `wrapped`、禁止 wrap 时报告未命中、查询完全不存在时即使允许 wrap 也报告未命中、跨代理对 Emoji 的匹配与 UTF-16 跨度计算。`document_store.rs` 原有的两个端到端集成测试（`repairs_truncated_journal_after_last_valid_transaction`、`falls_back_to_other_snapshot_slot_when_latest_is_corrupt`）保持不动、继续通过。
- 受保护范围：未修改 `src-tauri/src/main.rs`、`Cargo.toml`、`Cargo.lock`、`document_store/{validation,paths,repository,types}.rs`、`document_store/snapshot/*`、`document_store/journal/*`、`document_store/index/{builder,headings}.rs`、任何生产依赖、Tauri command 名称、DTO、磁盘布局、UTF-16 语义、搜索行为（wrap、大小写、起点钳制）。无新增生产依赖。

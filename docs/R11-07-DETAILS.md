# R11-07 — Writer/Loader (Snapshot Write Ordering, Two-Slot Loading)

- 基线与前置：本 Atomic 建立在本地 R11-06 Metadata/Integrity 改动之上（R11-04/05/06/07 均在本地未提交/推送）。**本地尚未推送到远程，均未经过真实 GitHub Actions CI 验证**；真实 CI 全部通过前不得视为已收口，不进入 R11-08。
- 任务书依据：执行 Stage 11 Atomic 11.7 Writer/Loader。目标是把快照写入顺序（fsync/rename 语义）与两槽加载从 `document_store.rs` 提取到独立文件；必须产出中断测试。
- Writer 边界：新增 `src-tauri/src/document_store/snapshot/writer.rs`，拥有 `write_snapshot(root, &mut StoredDocument)`——原样迁移自 `document_store.rs`，内部依次调用 11.5 的 `next_snapshot_slot`（决定写入非活动槽）、11.6 的 `build_snapshot_meta`、11.4 的 `write_atomic`（先内容、再元数据、再清空日志），更新 `document.snapshot_slot`。不决定何时触发快照（`SNAPSHOT_ENTRY_LIMIT`/`force_snapshot` 判定留在 `document_store.rs`）。
- Loader 边界：新增 `src-tauri/src/document_store/snapshot/loader.rs`，拥有 `load_active_snapshot(root) -> LoadedSnapshots { document, notes }`——原 `read_snapshot`（单槽读取+校验+构造 `StoredDocument`）整体迁入为私有辅助函数，新的两槽编排 `load_active_snapshot` 取代原 `load_document_from_disk` 开头的槽探测/读取/`select_active_slot`选择/notes 收集这一段，其余（日志重放、`recovery_message` 组装、恢复后重新快照）不属于 loader，留在 `document_store.rs`。
- 可见性：`StoredDocument`（定义于 `document_store.rs`、无显式修饰符）按 Rust 默认私有规则本就对 `document_store` 的全部子孙模块可见，`loader.rs`/`writer.rs` 直接构造/接收该类型，未做任何可见性放宽。（订正：R11-06 记录里把 `SnapshotMeta` 从 `pub(super)` 显式改写为 `pub(in crate::document_store)` 其实是等价操作，非必须放宽——`types.rs` 只比 `document_store` 深一层，`pub(super)` 本就能覆盖 `document_store` 的全部子孙模块；该记录里"必须放宽"的表述不准确，这里一并订正。）
- 不迁移范围：快照触发阈值判定（`SNAPSHOT_ENTRY_LIMIT`/`SNAPSHOT_BYTE_LIMIT`/`force_snapshot`）、日志重放与版本链校验、`recovery_message` 文本组装、恢复后重新落盘的编排，均原地留在 `document_store.rs`，划给 11.8 Journal Entry/Append 与 11.9 Replay/Recovery，本次未提前跨 Atomic 抽取。
- 编排保持：`document_store.rs` 的 `load_document_from_disk` 开头改为 `let loaded = load_active_snapshot(root); let mut recovery_notes = loaded.notes; let Some(mut document) = loaded.document else { ... };`，把原来 `(a_exists || b_exists)` 的错误判定等价改写为 `!recovery_notes.is_empty()`（两者在“document 为 None”这一分支下逻辑等价：`recovery_notes` 非空当且仅当至少一个槽存在但未通过校验）。后续日志重放、`write_snapshot` 调用点、Tauri command 均未改变调用方式。
- 兼容夹具：`document_store_compatibility.rs` 无需改动——本次迁移未涉及任何已冻结 token（均已在 R11-06 迁移时随 `fnv1a64` 常量一起纳入扫描范围）。
- 新契约测试：`snapshot/loader.rs` 自带 5 项单元测试（两槽皆空返回 `None` 且无 notes、按版本择优、单槽损坏时回退并记录对应 note、双槽皆损坏时 `document` 为 `None` 且带 note、经真实 `next_snapshot_slot` 轮换写入的槽可被正确加载）。`snapshot/writer.rs` 自带 3 项单元测试，其中 `write_snapshot_leaves_the_previous_slot_untouched_for_crash_recovery` 即任务书要求的中断测试——验证写入新快照后，旧快照的内容与元数据文件原封不动，证明"写入永远先到非活动槽"这一 fsync/rename 语义在中断/崩溃场景下不会破坏最近一次已知良好的快照。`document_store.rs` 原有的端到端集成测试 `falls_back_to_other_snapshot_slot_when_latest_is_corrupt`（模拟槽内容损坏，验证整条 `load_document_from_disk` 链路正确回退）与 `repairs_truncated_journal_after_last_valid_transaction` 保持不动、继续通过，作为 loader/writer 迁移后的端到端验证。
- 受保护范围：未修改 `src-tauri/src/main.rs`、`Cargo.toml`、`Cargo.lock`、`document_store/validation.rs`、`document_store/paths.rs`、`document_store/repository.rs`、`document_store/snapshot/{slots,metadata,integrity}.rs`、任何生产依赖、Tauri command 名称、DTO、磁盘布局、UTF-16/恢复语义。无新增生产依赖。

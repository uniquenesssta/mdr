# R11-05 — Snapshot Slots (Active/Inactive Selection and Fallback)

- 基线与前置：本 Atomic 建立在本地 R11-04 Repository 改动之上（均尚未提交/推送）。**本地尚未推送到远程，R11-03、R11-04、R11-05 均未经过真实 GitHub Actions CI 验证**；真实 CI 全部通过前不得视为已收口，不进入 R11-06。
- 任务书依据：执行 Stage 11 Atomic 11.5 Snapshot Slots。目标仅是把快照 A/B 槽的写入端选择（永远写入非活动槽）与读取端选择/回退（优先较高版本，一侧校验失败时回退到另一侧）从 `document_store.rs` 提取到独立的 `snapshot/slots.rs`。
- Snapshot Slots 边界：新增 `src-tauri/src/document_store/snapshot/mod.rs`（聚合入口，只做 `pub(super) use`，不拥有状态）与 `src-tauri/src/document_store/snapshot/slots.rs`，拥有 `next_snapshot_slot`（写入端：给定当前槽，返回应写入的非活动槽）与 `select_active_slot`（读取端：给定两个候选及版本提取闭包，返回版本更高者，单侧缺失时回退到另一侧，两侧都缺失返回 `None`）。`select_active_slot` 采用泛型 + 闭包而非直接依赖 `StoredDocument`，因为该类型对 `document_store.rs` 之外不可见；这不是为了假设性复用而设计的抽象——写入端与读取端本就是同一个"槽位选择"职责的两个真实、当下就要用到的入口，合并成一个模块符合任务书对 11.5 的定义。
- 不迁移范围：快照内容/元数据的哈希与字节数校验（`read_snapshot` 内部逻辑，划给 11.6 Metadata/Integrity）、快照写入的 fsync/rename 顺序与两槽加载编排（`write_snapshot`/`load_document_from_disk` 主体，划给 11.7 Writer/Loader）均原地不动，本次未提前跨 Atomic 抽取。
- 编排保持：`document_store.rs` 的 `write_snapshot` 改为调用 `next_snapshot_slot`（导入自 `snapshot`，函数名不变）；`load_document_from_disk` 原来的三分支 `match (snapshot_a, snapshot_b) { ... }` 改写为 `let Some(mut document) = select_active_slot(snapshot_a, snapshot_b, |item| item.version) else { ... }`，行为逐条对应原三个分支（双存在按版本择优、单存在直接采用、双缺失走原有错误/空返回路径），未改变错误文本、日志重放起点或恢复标记逻辑。
- 兼容夹具：`document_store_compatibility.rs` 的词法扫描范围与冻结 token 列表未变；本次迁移未涉及该测试冻结的任何 token，未扩展扫描范围到 `snapshot/`。
- 新契约测试：`snapshot/slots.rs` 自带 4 项单元测试——槽位交替（原 `document_store.rs` 测试原样迁移）、双候选按版本择优且同版本时偏向 A（保持原 `>=` 比较语义的可观察行为）、单候选回退、双候选缺失返回 `None`。`document_store.rs` 原有的 `alternates_snapshot_slots_without_overwriting_current_snapshot` 测试已删除（职责迁出，避免重复权威）；端到端回退验证继续由 `document_store.rs` 现有的 `falls_back_to_other_snapshot_slot_when_latest_is_corrupt` 集成测试覆盖（该测试同时验证 `read_snapshot` 完整性校验与槽位回退的组合行为，保留在原位置更合适）。
- 受保护范围：未修改 `src-tauri/src/main.rs`、`Cargo.toml`、`Cargo.lock`、`document_store/types.rs`、`document_store/validation.rs`、`document_store/paths.rs`、`document_store/repository.rs`、任何生产依赖、Tauri command 名称、DTO、磁盘布局、UTF-16/恢复语义。仅删除已迁移到 `snapshot/slots.rs` 的旧函数定义与重复测试，无其他删除候选，无新增生产依赖。
- 验证：本地执行（Rust 工具链 `rustup override set 1.88.0` 锁定，与 CI 一致）：`cargo test` 34 单元 + 5 兼容 = 39/39 通过（较 R11-04 的 36/36 净增 3：新增 4 项、删除 1 项重复）；`cargo clippy --all-targets -- --deny warnings` 通过；`cargo check` 通过；`rustfmt --check` 仅对新文件 `snapshot/mod.rs`、`snapshot/slots.rs` 执行并通过（未对 `document_store.rs` 做无关全文件格式化）；`npm test` 344/344 通过；`npm run verify:architecture` 通过；`npm run build` 通过。未运行 `npm run test:browser:contract`、`npm run test:browser`、Tauri release build——本 Atomic 只改变 Rust 内部模块边界，未改变任何 Tauri command 签名、DTO 或前端调用路径。

# R11-10 — Index Builder (Checkpoints, Headings, Line Count, Non-Whitespace Count)

- 基线与前置：本 Atomic 建立在本地 R11-09 Replay/Recovery 改动之上。沿用用户在本轮明确指示的方针——不再以真实 CI 结果作为开始各 Atomic 的前置条件，仅依赖本地验证结果推进。
- 任务书依据：执行 Stage 11 Atomic 11.10 Index Builder。目标是把文档索引构建（UTF-16 检查点、标题、行数、非空白字符数）从 `document_store.rs` 提取到独立文件；必须产出 fenced code 内标题处理一致。
- Headings 边界：新增 `src-tauri/src/document_store/index/headings.rs`，拥有三个纯函数：
  - `heading_id(line, level, text) -> String`——原样迁移，格式串与 fnv1a64 摘要逐字保留。
  - `parse_atx_heading(line) -> Option<(u8, String)>`——原样迁移，识别 1–6 个 `#`、要求标题号后是空白或行尾、裁剪尾部 `#` 和空白、空文本判定为非标题。
  - `fence_marker(line) -> Option<(char, usize)>`——原样迁移，识别 3 个及以上重复的反引号或波浪号。
  这三者不涉及整篇文档扫描、检查点、行数或非空白计数——那些留在 `builder`。
- Builder 边界：新增 `src-tauri/src/document_store/index/builder.rs`，拥有：
  - `DocumentIndex`/`IndexCheckpoint` 类型定义——从 `document_store.rs` 顶层结构体迁移而来（此前分别是裸 `struct`，现改为 `pub(in crate::document_store)`，字段同步改为该可见性，供 `document_store.rs` 的 `StoredDocument.index` 字段和仍留在原地的 `index_utf16_to_byte`/`index_byte_to_utf16`——划给 R11-11——继续按字段访问）。
  - `build_document_index(content) -> DocumentIndex`——原样迁移自 `document_store.rs` 同名函数，内部调用 `headings::{fence_marker, parse_atx_heading, heading_id}`；`INDEX_CHECKPOINT_BYTES` 常量随其一并迁移。
  - `ensure_document_index(&mut StoredDocument) -> &DocumentIndex`——原样迁移，懒加载缓存策略不变。
- 编排保持：`document_store.rs` 顶部新增 `mod index;` 与 `use index::{ensure_document_index, DocumentIndex};`；`StoredDocument` 结构体删除内联的 `DocumentIndex`/`IndexCheckpoint` 定义，`index` 字段类型改用导入的 `index::DocumentIndex`。`load_document_manifest`/`search_document_state` 两个 Tauri command 对 `ensure_document_index` 的调用点未改变签名或调用方式；仍留在 `document_store.rs` 的 `index_utf16_to_byte`/`index_byte_to_utf16`（R11-11 UTF-16/Search 范围）继续以 `&DocumentIndex` 作为参数类型不变。
- 导入清理：`heading_id` 是 `fnv1a64` 在 `document_store.rs` 内的唯一消费者，迁移后 `use snapshot::{fnv1a64, ...}` 里的 `fnv1a64` 成为该文件内的死引用，已移除（`fnv1a64` 本身仍由 `journal`/`snapshot` 内部按需各自导入，未受影响）。`pub(crate) use types::{...}` 里的 `NativeHeading` 同理——此前唯一的内部消费者是 `build_document_index` 里的 `NativeHeading { ... }` 字面量构造，迁移后该字面量改为直接 `use crate::document_store::types::NativeHeading;`（在 `index/builder.rs` 内），`document_store.rs` 自身与 crate 内其余位置均无消费者（已用 `grep -rn` 确认零外部引用），故一并从该 re-export 列表移除，与 R11-09 对 `DocumentTransaction` 的处理方式一致。`build_document_index` 在 `document_store.rs` 里现在只被 `#[cfg(test)]` 测试消费，其在 `index/mod.rs` 的聚合导出已加 `#[cfg(test)]`（`ensure_document_index`/`DocumentIndex` 仍是无条件导出，因为它们被生产代码路径使用）。
- 测试迁移：`document_store.rs` 原有的 `builds_sparse_index_and_ignores_fenced_headings` 拆分为两半——纯 `DocumentIndex` 结构断言（`line_count`/`headings`/`utf16_length`）随 `build_document_index` 迁移进 `index/builder.rs`，改名为 `build_document_index_finds_headings_outside_fences_and_counts_lines_and_length` 并补充了标题文本/层级断言；emoji 字节/UTF-16 往返断言（真正测试的是仍留在 `document_store.rs` 的 `index_byte_to_utf16`/`index_utf16_to_byte`，`build_document_index` 只是构造夹具）保留在 `document_store.rs`，改名为 `maps_utf16_and_byte_offsets_through_sparse_checkpoints_for_emoji`，未在原位置保留重复断言。
- 兼容夹具：`document_store_compatibility.rs` 无需改动——本次迁移未涉及任何冻结 token 所在文件（`fnv1a64`/`encode_utf16` 常量与用法均已在既有扫描范围内，标题/检查点逻辑本身不属于冻结 token 清单）。
- 新契约测试：`index/headings.rs` 自带 4 项单元测试——`heading_id` 对相同输入稳定、不同行号不同结果；`parse_atx_heading` 接受 1–6 级并裁剪尾部 `#`；拒绝 7 级、空文本、缺少分隔空白；`fence_marker` 要求 3 个及以上重复字符。`index/builder.rs` 自带 3 项单元测试——沿用并加强的 fenced-heading 结构断言、超过 64KB 阈值后检查点确实增多且非空白计数正确、`ensure_document_index` 只构建一次并缓存在文档上。`document_store.rs` 原有的两个端到端集成测试（`repairs_truncated_journal_after_last_valid_transaction`、`falls_back_to_other_snapshot_slot_when_latest_is_corrupt`）保持不动、继续通过。
- 受保护范围：未修改 `src-tauri/src/main.rs`、`Cargo.toml`、`Cargo.lock`、`document_store/{validation,paths,repository,types}.rs`、`document_store/snapshot/*`、`document_store/journal/*`、任何生产依赖、Tauri command 名称、DTO、磁盘布局、UTF-16 映射语义（`index_utf16_to_byte`/`index_byte_to_utf16` 本体未改动，仅参数类型来源变化）。无新增生产依赖。

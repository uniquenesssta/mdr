## 12. 重点风险与禁止处理方式

- 删除过早导致隐藏兼容路径丢失。
- 保留 wrapper 形成双实现。
- 测试通过但构建仍引用旧静态文件。
- 清理时夹带功能改动。
- 删除用户数据或正式夹具。

禁止用以下方式“解决”风险：

- 增加永久白名单
- 保留旧实现作为 fallback
- 捕获异常后静默忽略
- 用 mock 代替必须验证的真实调用链
- 降低测试断言或删除失败场景
- 通过 service locator、全局单例或通用 helpers 转移耦合

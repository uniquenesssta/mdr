## 1. 重写目标

本次重写不是“把大文件机械切小”，而是建立一套能够长期承接新增想法的稳定项目结构。完成后必须同时满足：

1. 每个目录代表一个明确能力域，不再以“哪里能放就放哪里”为依据。
2. 每个文件只有一个主要职责、一个主要状态所有者、一个可解释的变更原因。
3. UI 结构、UI 行为、业务流程、模型、持久化、平台调用和样式相互分层，不再混写。
4. 任何功能新增时，都能明确落入：
   - 功能域；
   - 应用流程；
   - 状态；
   - 平台适配；
   - UI 视图；
   - 样式；
   - 测试。
5. 删除经典脚本共享作用域、隐式加载顺序、`window.*` 全局业务 API、HTML 内联事件和巨型 CSS。
6. 保留模型算法、现有用户行为、Tauri 命令语义、文档格式、持久化格式、快捷键和大文档性能策略。
7. 最终只有一套生产实现，不留下临时兼容层、重复状态、转发空壳和历史副本。
8. 新想法进入项目时，不需要重新拆整个应用，也不需要继续膨胀 `core.js`、`events.js`、`main.css` 一类文件。

## 2. 本次“模型不重写”的边界

### 2.1 冻结原则

“模型”按当前代码中的算法与状态内核认定。冻结意味着：

- 不改变算法语义；
- 不改变输入输出结构；
- 不改变偏移量、版本号、事务、块范围、选择映射等契约；
- 不借重写之名调整模型结果；
- 允许新应用层通过适配器调用；
- 只有模型自身存在已确认缺陷且用户另行授权时，才进入独立任务。

### 2.2 初始冻结清单

以下文件或其核心算法默认作为模型内核保留：

| 当前文件 | 冻结内容 |
|---|---|
| `src/document/document-model.js` | 文档身份、代次、版本、事务日志、消费者确认、显式快照语义 |
| `src/preview/incremental-preview.js` | Markdown 增量块模型、稳定 ID、局部重解析与全文回退判定 |
| `src/editor/hybrid/table-model.js` | Markdown 表格行解析、单元格编码与序列化规则 |
| `src/editor/hybrid/math-ranges.js` | 数学公式范围识别和冲突排除规则 |
| `src/editor/hybrid/ranges.js` | 混合编辑可见范围、源码揭示范围和块范围判定 |
| `src/sync/selection-mapping.js` | 预览 DOM 与 Markdown 源码精确边界映射算法 |
| `src/preview/math-source.js` | 预览数学源码保护、恢复与分隔符判定 |
| `src/editor/hybrid/block-registry.js` | 混合模式块描述符生成规则；应用层只能消费描述符 |
| `src-tauri/src/document_store.rs` 中的数据格式契约 | 快照元数据、事务日志格式、双槽恢复规则、UTF-16/字节偏移语义；Rust 文件本身可重写拆分，但格式和结果不得变化 |

### 2.3 模型边界的实施方式

新增 `src/model-kernel/index.js` 作为**有价值的稳定入口**，仅统一导出冻结模型。业务模块不得越过该入口直接依赖多个模型内部文件。它不是无意义转发层，其作用是：

- 固定模型公共契约；
- 限制模型内部路径扩散；
- 让架构测试能够阻止 UI、平台层直接侵入模型；
- 将来模型内部路径变化时，应用层不需要全局重写。

任何后续由用户明确指定为模型的文件，都在实施前加入冻结清单。

## 3. 当前代码扫描后确认的主要问题

### 3.1 两套前端架构并存

当前 `src/main.js` 一方面使用 ES Module 创建编辑器、预览、同步和存储控制器，另一方面按固定顺序动态加载：

- `public/app/core.js`
- `public/app/scroll-sync.js`
- `public/app/bootstrap.js`
- `public/app/preview.js`
- `public/app/export.js`
- `public/app/editor-tools.js`
- `public/app/web-clipper.js`
- `public/app/events.js`

这些经典脚本共享同一全局词法环境，依赖“前一个文件先声明变量或函数”。结果是：

- 文件表面分开，真实职责并未分开；
- 依赖无法通过 `import` 看见；
- 调整加载顺序即可破坏运行；
- 测试难以独立加载单个模块；
- 新功能只能继续访问全局变量；
- 销毁与监听器清理没有统一所有者。

### 3.2 `public/app/core.js` 不是核心，而是多个系统的混合容器

该文件同时持有或参与：

- 本地存储键；
- 当前文档列表与最近文件；
- 侧栏状态；
- 布局模式；
- 分栏拖拽；
- 紧凑布局；
- 工具栏折行；
- 设置对话框；
- 主题；
- 字体与颜色；
- 自动保存配置；
- 预览策略；
- 历史兼容；
- 多个 DOM 查询和事件绑定。

这些职责变化原因完全不同，不能继续保留在同一文件。

### 3.3 UI 仍以单页巨型 HTML 为中心

`index.html` 当前包含：

- 图标精灵；
- 菜单栏；
- 工具栏；
- 工作区；
- 侧栏；
- 编辑器与预览容器；
- 多个设置页；
- 帮助、链接、图片、表格、Mermaid、网页导入、导出图片等模态框；
- 大量 `onclick`、`onchange`、`oninput` 内联事件。

这使 UI 结构与全局函数名称强绑定，任何功能改动都可能跨越 HTML、经典脚本和 CSS 三个巨型文件。

### 3.4 UI 样式没有职责边界

`src/styles/main.css` 同时包含：

- 设计令牌；
- 明暗主题；
- Reset；
- 应用壳；
- 菜单；
- 工具栏；
- 侧栏；
- 编辑器；
- 预览；
- 混合编辑组件；
- 模态框；
- 设置；
- 导出；
- 响应式布局；
- 动画；
- 窗口控件。

后续任何 UI 想法都会继续增加选择器冲突和不可预测的级联影响。

### 3.5 大文件职责堆积

当前已确认的高风险文件包括：

- `src/editor/hybrid/widgets.js`：大量不同类型组件、交互、编辑、生命周期和 DOM 构建；
- `src/editor/hybrid/inline-presentation.js`：多类 Markdown 行内展示规则混在一起；
- `public/app/preview.js`：调度、模式、布局稳定、Worker、虚拟化、渲染、增强、定位混合；
- `public/app/scroll-sync.js`：旧编辑器度量、滚动映射、选区映射和兼容逻辑混合；
- `public/app/export.js`：自动保存、导出任务、全量渲染、各格式导出、图片导出混合；
- `public/app/editor-tools.js`：历史、格式化、颜色、插入、查找、多个弹窗混合；
- `src/runtime/tauri.js`：窗口、对话框、文件、文档存储、拖放、网页、日志统一暴露在一个对象；
- `src-tauri/src/document_store.rs`：命令 DTO、验证、路径、索引、快照、日志、恢复、搜索和上传会话集中；
- `src-tauri/src/local_file.rs`：路径安全、目录扫描、文本、图片、写入、格式识别集中。

### 3.6 状态所有权不清晰

同一种状态在不同位置被读取或修改：

- 文档正文：编辑器、DocumentModel、预览、保存、导出；
- 当前文档：经典脚本数组、DocumentModel、NativeDocumentStore；
- 预览状态：布局、Worker、虚拟预览、同步；
- 保存状态：自动保存、手动保存、关闭窗口；
- UI 状态：DOM class、局部变量、localStorage；
- 组件编辑状态：CodeMirror 插件、Widget、全局事件。

重写必须为每项状态指定唯一所有者。

### 3.7 测试过度依赖旧文件文本

现有部分契约测试直接读取特定文件并用正则判断实现文本。重写后应保留行为契约，但不能继续把“某段代码必须位于旧文件”当成架构要求。

## 4. 不可违反的目标架构规则

### 4.1 依赖方向

```text
模型内核
   ↑
共享基础原语
   ↑
平台端口与适配器
   ↑
功能域：domain / application / infrastructure / ui
   ↑
应用组合根与生命周期
```

具体规则：

1. `src/app/` 可以组合所有功能，但功能模块不得反向导入 `src/app/`。
2. `src/features/<feature>/ui/` 只能调用本功能的应用 API，不能直接调用 Tauri、localStorage、Worker。
3. `src/features/<feature>/infrastructure/` 实现端口，但不操作其他功能的 UI。
4. `src/platform/` 不导入任何业务功能。
5. `src/model-kernel/` 不导入 UI、平台和应用层。
6. 功能之间只能通过各自 `index.js` 暴露的公共 API 通信，禁止导入另一个功能的内部路径。
7. 样式不能通过深层选择器控制不属于自己的功能。
8. Rust `commands/` 只负责参数接收和错误映射，实际逻辑必须进入能力目录。
9. 禁止循环依赖。
10. 禁止在模块导入时自动注册监听器或产生运行副作用。

### 4.2 状态所有权

| 状态 | 唯一所有者 |
|---|---|
| 正文、版本、事务、代次 | `DocumentModel` |
| 当前会话文档和文档列表 | `documents` 功能 |
| 最近打开文件 | `documents/infrastructure/recent-files-repository.js` |
| 编辑器选择、焦点、只读状态 | `editor` 功能 |
| 混合组件展示/直接编辑/源码编辑 | `hybrid-editor` 功能，模型状态保持现有语义 |
| 预览模式、版本、渲染任务 | `preview` 功能 |
| 滚动源所有权 | `sync/scroll` |
| 选区同步状态 | `sync/selection` |
| 自动保存队列和保存状态 | `persistence` 功能 |
| 导出任务 | `export` 功能 |
| 布局、侧栏宽度、分栏比例、紧凑模式 | `layout` 功能 |
| 设置值 | `settings` 功能 |
| 语言 | `i18n` 服务 |
| 菜单打开状态 | `menu` 功能 |
| Toast/确认框队列 | `notifications` 功能 |
| 桌面窗口状态 | `window` 功能 |
| 性能日志缓冲 | `telemetry` 功能 |

### 4.3 文件升级为目录的规则

当现有文件需要拆分时，必须执行“能力目录提升”，不能继续把新逻辑塞回原文件。

示例：

```text
原：
src/storage/native-document-store.js

目标：
src/features/persistence/native-document-store/
  index.js
  native-document-store.js
  native-save-session.js
  native-save-queue.js
  native-snapshot-uploader.js
  native-segment-loader.js
```

规则：

1. 原文件不再承载实现。
2. 若外部路径不需要兼容，删除原文件，统一导入目录 `index.js`。
3. 若现有公共导入路径必须暂时保留，原路径只能成为短期兼容门面：
   - 只导出公共 API；
   - 不持有状态；
   - 不绑定事件；
   - 不包含业务分支；
   - 当前阶段结束前删除。
4. 不创建 `native-document-store-old.js`、`new.js`、`v2.js`、`final.js`。
5. 拆分后的文件必须使用职责名称，而不是先后版本名称。
6. 同目录下出现新的独立能力时，优先创建子目录，而不是继续扩大入口文件。

### 4.4 文件规模软门禁

文件大小不是唯一依据，但作为风险告警：

- 0–300 行：通常可接受；
- 301–450 行：必须检查是否仍为单一职责；
- 451–600 行：必须在代码审查中说明为何不能继续拆分；
- 超过 600 行：默认不允许进入生产，除非它是不可拆分的数据表、生成代码或高度内聚的算法模型；
- `index.js` 公共入口建议不超过 120 行；
- UI 模板文件超过 300 行时，应按视觉区域或组件职责拆分；
- CSS 文件超过 350 行时，应按组件或功能继续拆分；
- Rust 模块超过 500 行时，应检查命令、类型、存储、校验、恢复是否混合。

这些是告警线，不是为了制造“一函数一文件”。

## 6. 前端完整目录与每个文件职责

### 6.1 应用组合根 `src/app/`

```text
src/app/
├─ create-application.js
├─ application-context.js
├─ lifecycle/
│  ├─ application-lifecycle.js
│  ├─ disposer-registry.js
│  ├─ startup-sequence.js
│  └─ shutdown-sequence.js
├─ commands/
│  ├─ command-bus.js
│  ├─ command-registry.js
│  └─ command-ids.js
└─ events/
   ├─ event-bus.js
   └─ event-types.js
```

| 文件 | 唯一职责 |
|---|---|
| `src/main.js` | 唯一浏览器入口；创建应用并调用 `start()`；捕获不可恢复启动错误；不得包含业务逻辑 |
| `create-application.js` | 组合功能模块、平台适配器、UI 插槽和模型；返回应用对象 |
| `application-context.js` | 保存组合期依赖引用；只允许组合根读取，不作为全局状态仓库 |
| `application-lifecycle.js` | 对外提供幂等 `start()` / `destroy()`；保证逆序销毁 |
| `disposer-registry.js` | 统一登记监听器、Observer、Worker、计时器和订阅的清理函数 |
| `startup-sequence.js` | 定义启动阶段及依赖顺序；每阶段失败时执行已启动阶段回滚 |
| `shutdown-sequence.js` | 编排关闭前保存、任务取消、Worker 终止、监听器解绑 |
| `command-bus.js` | 接收 UI 命令并路由到注册处理器；不保存业务状态 |
| `command-registry.js` | 注册/注销命令处理器；阻止重复命令 ID |

禁止：

### 8.1 CSS 边界规则

1. `tokens.css` 只定义语义变量，不写组件选择器。
2. `light.css` / `dark.css` 只覆盖令牌，不复制组件样式。
3. 组件样式不得使用页面结构深层选择器。
4. 功能样式使用命名空间：
   - `.c-*`：通用组件；
   - `.l-*`：布局；
   - `.f-<feature>-*`：功能 UI；
   - `.is-*`：瞬时状态；
   - `.has-*`：拥有状态。
5. 禁止通过 `#id` 参与视觉样式，ID 只用于可访问性关联或挂载。
6. 禁止大面积 `!important`。
7. 禁止内联 `style` 承载稳定视觉；动态尺寸只设置 CSS 变量。
8. 每个功能只导入自己的样式入口。
9. 删除 `main.css` 后，`index.css` 只按依赖顺序导入，不写实际组件规则。
10. 混合编辑和预览代码块共享设计令牌，但各自保留布局样式，避免跨功能选择器耦合。

- `<head>` 元信息；

- `store.rs`：内存会话和命令用例编排。

- `snapshot/*`：双槽快照完整链路。
- `journal/*`：事务日志追加、重放、截断恢复。
- `index/*`：标题、UTF-16 检查点、搜索。
- `chunks/*`：分块读取和上传会话。
- `local_file/path_policy.rs`：路径和符号链接安全。
- `directory_tree.rs`：有界目录树扫描。
- `tree_limits.rs`：扫描上限与截断策略。
- `external_link/validation.rs`：允许协议。
- `web_fetch/client.rs`：reqwest 客户端配置。
- `performance_log/redaction.rs`：日志敏感字段清理。

### 9.2 Rust 兼容要求

以下不能改变：

- Tauri 命令名称；
- 前端请求字段；
- 返回字段；
- camelCase 序列化；
- 快照目录和文件兼容；
- 双槽选择与回退语义；
- journal 版本连续性；
- UTF-16 偏移；
- 中文与 Emoji 搜索位置；

- 外部链接协议白名单；
- 日志不记录正文和完整路径。

## 11. 关键运行链路设计

### 11.1 启动链路

```text
src/main.js
→ createApplication()
→ createPlatform()
→ createUi()
→ create model adapters
→ create feature controllers
→ lifecycle.start()
   1. telemetry
   2. i18n
   3. settings
   4. UI shell
   5. document session
   6. editor
   7. preview
   8. persistence
   9. sync
   10. menus/layout/window/import/export
→ app ready
```

要求：

- 任一步失败，已启动模块逆序销毁；
- `start()` 重复调用无副作用；
- 初始化期间不依赖隐藏全局函数；
- UI 首帧可先出现壳，再加载正文；
- 大文档恢复继续分段。

### 11.2 编辑链路

```text
用户输入
→ CodeMirror adapter 产生事务
→ DocumentModel 更新版本和 journal
→ 发布 document.changed
├─ preview scheduler 接收
├─ autosave controller 接收
├─ outline controller 接收结构变化
├─ word-count/statistics 接收增量统计
└─ telemetry 记录聚合指标
```

任何订阅者不得反向直接修改 DocumentModel 内部字段。

### 11.3 预览链路

```text
document.changed
→ preview-scheduler 合并
→ preview-mode-resolver
→ preview-render-coordinator
   ├─ Worker 增量模型
   ├─ 当前章节
   ├─ 全文虚拟
   └─ 完整预览
→ preview-node-factory
→ virtual-preview or direct DOM
→ enhancement coordinator
→ geometry changed event
→ sync recalibration
```

每个异步结果必须携带：

- 文档 ID；
- 文档代次；
- 编辑版本；
- 预览请求序号。

任何一项过时即丢弃。

### 11.4 保存链路

```text
document.changed
→ autosave-controller debounce
→ save-controller
→ browser or native store
→ save-status-store
→ save-status-view
```

关闭窗口：

```text
window close request
→ window-close-controller
→ close-save-controller
→ 等待当前保存队列
→ 强制最终快照
→ 成功：commit close
→ 失败：确认返回编辑或仍然关闭
```

### 11.5 文件打开链路

```text
菜单 / 文件树 / 拖放
→ import or document-open coordinator
→ classify path/file
→ persistence load
→ DocumentModel.activate
→ editor reset
→ preview reset
→ outline/index restore
→ document session activate
→ recent files update
```

旧加载请求在新文件打开后必须取消，不能覆盖新文档。

### 11.6 导出链路

```text
export command
→ export-controller
→ export-task-controller
→ export-document-builder
→ format exporter
→ platform save dialog/file writer
→ task complete/cancel/error
```

导出期间不修改当前预览 DOM；需要打印时使用隔离的打印容器或显式恢复流程。

### 11.7 设置链路

```text
settings dialog
→ settings validation
→ settings repository
→ settings store
→ settings.changed event
├─ theme
├─ editor
├─ layout
├─ toolbar
├─ autosave
└─ preview mode
```

设置模块不直接调用这些功能。

## 12. 新想法进入项目时的落位规则

后续新增任何想法，先按以下顺序判断：

1. 是否属于现有功能的同一职责？
   - 是：进入该功能对应的 application/domain/infrastructure/ui。
2. 是否拥有独立状态、生命周期、外部依赖或 UI？
   - 是：在 `src/features/<new-feature>/` 创建新能力目录。
3. 是否只是跨功能命令？
   - 在命令总线注册，处理器仍属于真实功能。
4. 是否是平台能力？
   - 进入 `src/platform/`，不进入功能 UI。
5. 是否是通用视觉组件？
   - 只有至少两个功能真实复用后进入 `src/ui/components/`。
6. 是否是通用算法原语？
   - 只有跨功能真实复用且无业务语义时，才进入共享目录。
7. 禁止把新想法放入：
   - `core.js`；
   - `events.js`；
   - `helpers.js`；
   - `utils.js`；
   - `misc.js`；
   - `main.css`；
   - `window.*` 全局对象。

示例：

- 新增云同步：`features/cloud-sync/`，通过持久化端口与文档事件工作；
- 新增 AI 写作：`features/ai-assistant/`，通过编辑命令提交事务，不能直接改 CodeMirror 内部；
- 新增评论：`features/comments/`，拥有自己的 domain/application/ui；
- 新增标签页：`features/workspace-tabs/`，不塞进 documents 或 layout；
- 新增插件系统：只有形成明确需求后建立独立功能，不预先实现空泛扩展框架。

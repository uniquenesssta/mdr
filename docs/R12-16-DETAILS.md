## 职责与兼容性

`performance_log/lifecycle.rs` 独立负责 `app.lifecycle` 事件投影，复用同一 `record_backend` → Writer → Paths/Redaction 链路。入口通过 `pub use` 保持 `performance_log::record_lifecycle` 公共路径，没有转发函数、额外状态、线程、队列或锁。Paths、Writer、Redaction、前端、依赖、命令列表与 `main.rs` 字节保持基线一致。

`main.rs` 仍在 Tauri Builder 前记录 `app.start`，在 `run` 返回后、主应用错误传播前记录 `app.exit`。日志错误只输出原有诊断，不能替换应用结果或阻止调用者继续。异常终止进程不保证退出日志，这是原行为，不新增崩溃处理或退出钩子。

本模块是同步无状态投影，没有异步取消、过时结果或独立销毁资源；重复调用按原语义重复记录。进程缓存和写锁继续由 R12-15 的唯一所有者管理，不制造虚假生命周期对象。

## 验证设计与证据边界

同一 `lifecycle_contract.rs` 分别在精确基线及当前实现上执行，包含五个真实文件场景及一个子进程入口，共 6 项：

- 启动/前端记录/退出在同一 JSONL 中的顺序、字段、PID、零耗时和单文件共享。
- 目录被文件阻塞：启动及退出记录失败后调用者继续，恢复目录后能够继续写入。
- 文件路径被目录阻塞：真实打开失败不会阻止调用者，移除阻塞后恢复。
- 独立进程中的真实 Writer 锁中毒：两种生命周期调用均返回，并保留错误诊断。
- 重复启动/退出不引入去重或待清理的后台工作。

所有环境覆盖通过子进程传入，文件目录由 RAII 清理，不修改父进程环境。独立 release harness 以关闭 debug assertions 的方式编译当前生产函数，验证生命周期调用不创建目录/文件；仅移除 Tauri 命令属性及测试模块挂载，不改写函数体。这不是完整 Tauri release GUI 启动验收。

保留 Windows Writer、Redaction、真实前端 payload→Rust JSONL、全量 Rust、Clippy、原生链接、前端构建和浏览器回归。新增 5 项静态契约验证迁移函数一致、启动/退出调用顺序、非传播错误、公共入口、真实职责清单和 Windows 验证路由。

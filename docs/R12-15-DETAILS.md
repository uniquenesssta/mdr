## 实现与职责

- `performance_log/paths.rs`：开发默认目录、`MARKDOWN_EDITOR_LOG_DIR` 覆盖、UTC 文件名、进程级 `LOG_FILE_PATH`。
- `performance_log/writer.rs`：唯一 `WRITE_LOCK`、debug 开关、500 条批次/64 KiB 序列化条目限制、脱敏后序列化、追加/换行/刷新与原错误映射。
- `performance_log.rs`：保留公开命令、后端指标/生命周期封装；现有调用者仍使用同一个入口，无新转发层或重复状态。
- `redaction.rs`、前端 payload/适配器、注册命令、依赖与日志格式保持基线不变。路径/写入函数体迁移前后进行契约比较。

实际调用关系：桌面日志命令或后端测量 → Writer → Paths 取得同一会话文件；Writer 在同一互斥区间内逐条调用 Redaction，再序列化、追加和刷新。release 在调用 Paths 前返回空路径，不能创建目录或文件。

A04 的部分批次成功后报错/整批重试风险没有在本项修复。新增回归明确保留“首条已落盘、后续超限报错”的事实，不把结构拆分当成确认/去重协议已实现。它继续归 R15.4/15.7，R12-24 复核是否需要提前止损。

## 验证与过时断言迁移

同一组 9 个测试入口（8 个隔离文件场景与一个子进程入口）在基线和当前实现各执行一次，真实调用 `write_performance_logs`，无模拟文件系统：

1. 自定义中文/空格目录、UTC 会话命名、空批次不创建文件及缓存稳定。
2. JSONL 多次追加、顺序、UTF-8、换行与脱敏。
3. 500 条允许、501 条在创建目录前拒绝。
4. 64 KiB 恰好允许、多 1 字节拒绝；失败后仍能追加。
5. 部分批次失败如实返回并保留已写行（A04 未关闭）。
6. 目录创建失败与同进程修复后重试。
7. 文件打开失败与同一会话恢复。
8. 8 线程、64 批次、640 行共享同一文件，无丢失、重复或批次交错。

补充 UTC epoch/闰日/跨年测试，以及 Windows `rustc -C debug-assertions=no` 编译真实 Paths/Writer/Redaction 的独立 release 模式 harness：空批次、普通输入与超量批次均不得创建目录。它验证生产写入边界的编译模式行为，不冒充完整 Tauri release 安装包或 GUI 验收。保留 R12-14 的 14 项脱敏和真实 JS payload→Rust→JSONL 回读。

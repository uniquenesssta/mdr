# R11-12 — Chunk Reader (Safe UTF-8 Boundary Reads, Offset Advance)

- 基线与前置：本 Atomic 建立在本地 R11-11 UTF-16/Search 改动之上。沿用用户在本轮明确指示的方针——不再以真实 CI 结果作为开始各 Atomic 的前置条件，仅依赖本地验证结果推进。
- 任务书依据：执行 Stage 11 Atomic 11.12 Chunk Reader。目标是把按安全 UTF-8 边界分段读取、offset 前进的逻辑从 `document_store.rs` 提取到独立文件；必须产出空文档和边界覆盖的测试证据。
- Reader 边界：新增 `src-tauri/src/document_store/chunks/reader.rs`，拥有 `read_chunk(content, byte_offset, max_bytes) -> Result<DocumentChunkRead, String>`——原样迁移自 `read_document_chunk` command 内联的分段逻辑（起点校验、`max_bytes.clamp(16*1024, 2*1024*1024)`、`end` 先钳制到文档末尾再向前回退到最近的字符边界、`end == byte_offset` 时的兜底前进一个字符分支、`done = end >= total_bytes`），错误文案“文档分段读取位置无效”逐字保留，返回类型改为 `DocumentChunkRead { next_byte_offset, total_bytes, content, done }` 结构体供调用方按字段读取。不涉及文档加载、缓存或分段上传会话状态——那些留在 store 编排层与划给 R11-13 的 Upload Session。
- 编排保持：`document_store.rs` 的 `read_document_chunk` command 收窄为：取用缓存文档 → 调用 `read_chunk` → 把返回结构体的字段映射进 `DocumentChunk`（补上调用方已知的 `document_id`/`byte_offset`）。Tauri command 名称、参数、`DocumentChunk` DTO 未变。
- 导入清理：`document_store.rs` 顶层新增 `mod chunks;` 与 `use chunks::read_chunk;`（按字母序插在 `mod index;` 之前）。
- 兼容夹具：`document_store_compatibility.rs` 无需改动——本次迁移未涉及任何冻结 token 所在文件，分段读取逻辑本身也不在冻结 token 清单内。
- 新契约测试：`chunks/reader.rs` 自带 7 项单元测试，覆盖任务书明确要求的“空文档和边界覆盖”：空文档返回单个已完成的空分段；起点恰好落在文档末尾同样返回已完成空分段；起点超过文档长度报错；起点落在多字节字符中间报错；小请求量在钳制后仍能一次读完小文档；针对 >16KiB 文档验证请求量钳制到最小 16KiB 后若落点恰好切在多字节字符中间会回退到该字符之前的边界（用 `"a".repeat(16_383) + "甲乙丙"` 构造，第 16384 字节恰好切入 3 字节的“甲”内部）；针对约 45KB 的重复中文内容验证连续调用 `read_chunk` 并把返回的 `next_byte_offset` 作为下一次调用的起点，能不重不漏地把整篇文档读完且产生多个分段（验证“offset 前进”这一交付物在真实跨块场景下成立）。原实现里 `end == byte_offset && byte_offset < total_bytes` 的兜底前进分支在当前 16KiB 最小钳制值下，由于任何合法 UTF-8 字符最多占 4 字节、检索区间内必然存在边界，经分析在此调用约束下不可达——原样保留该分支（不属于本次改动范围，也未被现有测试断言触发到），未编造无法通过公开接口触发的测试来强行覆盖它。
- 受保护范围：未修改 `src-tauri/src/main.rs`、`Cargo.toml`、`Cargo.lock`、`document_store/{validation,paths,repository,types}.rs`、`document_store/snapshot/*`、`document_store/journal/*`、`document_store/index/*`、任何生产依赖、Tauri command 名称、DTO、磁盘布局、分段读取阈值（16KiB–2MiB）。无新增生产依赖。
- 验证：本地执行（Rust 工具链 `rustup override set 1.88.0` 锁定，与 CI 一致）：`cargo test` 84 单元 + 5 兼容 = 89/89 通过（较 R11-11 的 77+5=82 净增 7）；`cargo clippy --all-targets -- -D warnings` 通过；`cargo check` 通过；`rustfmt --check --edition 2021` 对 `chunks/{mod,reader}.rs` 通过（对 `document_store.rs` 单独执行时报出的差异——`pub(crate) use types::{...}` 位置问题、一处多余空行——均已确认为此前 Atomic 已存在、未被本次改动触及的历史格式漂移）；`npm test` 344/344 通过；`npm run verify:architecture` 通过；`npm run build` 通过，未产生新的未跟踪构建/日志产物。未运行 `npm run test:browser:contract`、`npm run test:browser`、Tauri release build——本 Atomic 只改变 Rust 内部模块边界，未改变任何 Tauri command 签名、DTO 或前端调用路径。

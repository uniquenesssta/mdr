- 任务书依据：执行 Stage 11 Atomic 11.8 Journal Entry/Append。目标是把增量日志记录的序列化与追加从 `document_store.rs` 提取到独立文件；必须产出字节内容兼容。
- Entry 边界：新增 `src-tauri/src/document_store/journal/entry.rs`，拥有 `encode_journal_entry(&JournalEntry) -> Result<Vec<u8>, String>`——原样迁移自 `document_store.rs` 的 `append_journal` 函数体前半段（`serde_json::to_vec` 序列化 + 末尾追加 `\n`），错误文案“无法序列化增量日志：{err}”逐字保留。`JournalEntry` 类型定义本身不迁移，继续留在 `types.rs`（R11-02 已确立的边界）——`journal::entry`/`journal::append` 作为 `document_store` 的子孙模块，依据 `pub(super)` 可见性规则本就能直接引用其字段（R11-07 记录已就 `pub(super)` 的这一覆盖范围做过订正说明），未做任何可见性放宽。
- Append 边界：新增 `src-tauri/src/document_store/journal/append.rs`，拥有 `append_journal(root, &JournalEntry) -> Result<u64, String>`——调用 `entry::encode_journal_entry` 取得编码字节后，原样迁移原函数体后半段（`OpenOptions::new().create(true).append(true).open(...)` 打开、`write_all`、`sync_data`），错误文案“无法打开/写入/同步增量日志：{err}”逐字保留，返回值仍为编码后字节长度。不决定何时触发追加（由 `document_store.rs` 的 `save_document_inner` 调用点决定）、不做版本链连续性校验（`base_version`/`next_version` 的连续性校验属于重放路径，划给 11.9 Replay/Recovery）。
- 聚合层：`journal/mod.rs` 仅 `pub(super) use append::append_journal;`，对齐 R11-07 收尾时把 `snapshot/mod.rs` 收窄到实际调用方需要的符号这一先例——`document_store.rs` 只需要 `append_journal` 一个入口。
- 编排保持：`document_store.rs` 顶部新增 `mod journal;` 与 `use journal::append_journal;`（按字母序插入 `mod paths;` 之前），删除原 `fn append_journal` 实现；`save_document_inner` 的调用点 `append_journal(root, &entry)?` 未改变签名或调用方式。
- 导入清理：移除后 `OpenOptions`/`io::Write` 在 `document_store.rs` 主体代码中不再被生产代码使用（仅 `#[cfg(test)]` 里 `repairs_truncated_journal_after_last_valid_transaction` 测试手动破坏 journal 文件时用到），已将这两个导入从顶层 `use std::{...}` 收窄移入 `mod tests` 内部的 `use std::fs::OpenOptions；use std::io::Write；`，避免非测试编译单元下的 unused-import 警告（已用 `cargo check`——不带 `--all-targets`——验证过收窄前会告警、收窄后干净）。
- 兼容夹具：`document_store_compatibility.rs` 无需改动——序列化字节格式（字段顺序、camelCase、`\n` 结尾）完全未变，未涉及任何新增冻结 token。
- 新契约测试：`journal/entry.rs` 自带 2 项单元测试——`encode_journal_entry_keeps_the_exact_camel_case_json_and_trailing_newline`（逐字节比对期望 JSON 文本并确认末尾恰好一个 `\n`，即任务书要求的“字节内容兼容”）与 `encode_journal_entry_is_deterministic_across_repeated_calls`（同一输入两次编码字节相同，是重放路径对“同一记录可重复得到相同字节”这一前提的最小证明，服务于“版本连续”场景下 11.9 对日志行的逐行重放）。`journal/append.rs` 自带 2 项单元测试——验证文件缺失时创建并返回编码字节长度、多次追加按调用顺序落盘且不截断先前记录（`journalEntries`/`journal_bytes` 累加语义依赖此顺序保证）。`document_store.rs` 原有的 `repairs_truncated_journal_after_last_valid_transaction` 集成测试（模拟追加后再手动写入半条记录，验证截断恢复整条链路）保持不动、继续通过，作为 entry/append 迁移后的端到端验证。

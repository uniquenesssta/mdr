## 7. 公共契约与状态边界

### 7.1 必须稳定的公共契约

- `Application.start(): Promise<void>`
- `Application.destroy(): Promise<void>`
- `CommandBus.register(id, handler): disposer`
- `CommandBus.execute(id, payload): Promise<unknown>`
- `EventBus.subscribe(type, listener): disposer`
- `EventBus.publish(type, immutablePayload): void`
- `DisposerRegistry.add(disposer): disposer`
- `ModelKernel 只读导出契约`

### 7.2 状态所有权要求

- 本阶段新增状态必须由一个明确的 store/session/controller 唯一拥有。
- View 只能持有临时 DOM 引用和纯展示状态。
- 跨功能通信只能使用命令、只读事件或显式端口。
- 平台对象、模型对象、DOM 元素不得被塞入通用全局容器。
- 异步结果必须携带足以判断过时的 generation/version/requestId。
- 销毁后不得再发布事件、提交 DOM 或写入状态。

## 12. 重点风险与禁止处理方式

- 组合根成为新的 service locator。
- event bus 被滥用为业务状态仓库。
- 命令 ID 继续以散落字符串存在。
- 架构测试只检查文件名而不检查依赖。
- 为了通过门禁添加白名单。

禁止用以下方式“解决”风险：

- 增加永久白名单
- 保留旧实现作为 fallback
- 捕获异常后静默忽略
- 用 mock 代替必须验证的真实调用链
- 降低测试断言或删除失败场景
- 通过 service locator、全局单例或通用 helpers 转移耦合

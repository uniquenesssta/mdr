9. 执行阶段回归。
10. 更新 README 并审查最终 diff。

## 11. 测试与验证计划

### 11.1 单元验证

- 纯函数边界值、非法输入和空输入
- 状态转换、重复调用和幂等性
- 异步过时结果丢弃
- 错误与取消的区别
- start/destroy、监听器和计时器清理
- 公共 API 的输入输出契约

### 11.2 集成验证

- 本阶段模块与上一阶段公共端口连接
- 真实 DocumentModel/平台端口/DOM 壳的必要调用链
- 浏览器与桌面能力差异
- 上游命令到下游状态和 UI 的完整链路
- 失败后状态恢复和再次操作

### 11.3 架构验证

- 无跨 feature 内部路径导入
- 无循环依赖
- 无业务 `window.*`
- 无 HTML 内联事件
- 无模块导入副作用
- 无 old/new/v2/final/copy 文件
- 每个新目录有单一 public `index.js`，内部文件不被外部越过

## 12. 重点风险与禁止处理方式

- 导出和自动保存继续耦合。
- PDF 后预览不恢复。
- HTML/Word 模板重复。
- 取消后任务继续提交 UI。
- 图片资源失败导致整任务挂死。

禁止用以下方式“解决”风险：

- 增加永久白名单
- 保留旧实现作为 fallback
- 捕获异常后静默忽略
- 用 mock 代替必须验证的真实调用链
- 降低测试断言或删除失败场景
- 通过 service locator、全局单例或通用 helpers 转移耦合

## 13. 回退方案

1. 本阶段开始前记录可回退提交。
2. 每个 Atomic Task 独立提交，提交信息只描述该职责。
3. 任务失败时只回退当前 Atomic Task，不回退用户或前序阶段修改。
4. 如果公共契约已切换但验证失败，优先修复当前契约；无法在本任务内安全修复时，回退该任务的调用者切换和新文件。
5. 不通过恢复旧全局实现、复制旧文件或开启双实现作为临时回退。
6. 涉及持久化或数据格式时，回退前先验证新代码未写入不兼容数据。
